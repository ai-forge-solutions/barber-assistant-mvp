# Hermes rules — Barber Assistant MVP

## Project context

- Linear Project: `Barber assistant`
- GitHub repo: `ai-forge-solutions/barber-assistant-mvp`
- Product: TURNO., SaaS for barber appointment management.

## Required repository instructions

Before changing code, read:

1. `AGENTS.md`
2. `.github/skills/frontend-branding/SKILL.md` for every UI/frontend/copy/design change

## Branding rule

For any visible UI, landing, dashboard, public booking page, copy, or component work, always apply:

```text
.github/skills/frontend-branding/SKILL.md
```

This is strict. Do not introduce colors, fonts, radius, copy tone, or visual patterns outside the TURNO. design system.

## Branching and deployment

- `main` deploys production automatically on Netlify.
- Do not work directly on `main`.
- Do not open normal feature PRs against `main`.
- Do not merge/promote to `main` without Miguel's explicit approval.
- Use `develop` as the integration/staging branch.
- Create task branches from latest `origin/develop`.
- Open normal task PRs targeting `develop`.

Recommended branch names:

```text
feat/<linear-id>-short-title
fix/<linear-id>-short-title
chore/<linear-id>-short-title
```

## Validation

Use npm because `package-lock.json` is present.

Minimum validation before PR:

```bash
npm run lint
npm run build
```

When relevant, also run locally:

```bash
npm run dev
```

If environment variables or external services block validation, report the blocker explicitly and include any partial checks that were run.

## Linear delivery

For Linear tasks assigned to Hermes:

- Move to `In Progress by Hermes` when work starts.
- Open PR against `develop`.
- Move to `PR Opened` once the PR is ready.
- Comment with summary, validation evidence, PR URL, and production promotion status.

Production promotion means `develop -> main`; it is always a separate Miguel-approved step.
